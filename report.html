三、8 个位置组

8 是 2 的倍数，所以组 0 / 2 / 4 / 6 就是偶数位置，组 1 / 3 / 5 / 7 是奇数位置。

四、这个差距是真的吗

是真的，不是运气，也不是靠一两道题。
但具体多大不确定：重做一次，可能落在 +1.8 到 +17.5 之间。

好比两个班考试：甲班平均 80 分，乙班 70 分。你会追问两件事：这 10 分会不会是抽到的学生碰巧强？会不会是一两个学霸拉高的？下面三个办法，就是查这两件事。

办法一：换一批题，重算

64 道题（每道是一对固定的「键:值」）就是我们的「学生名单」。把 64 道题有放回地随机重抓 64 道（同一道可能被抓到多次），重算一次「偶数位减奇数位」。重复 10 万次，得到 10 万个差距。

横轴 = 一次重算得到的差距（百分点）。竖轴 = 有多少次重算落到这个差距，柱子越高越常见。0 = 两边一样准。10 万个差距里，99.2% 在 0 右边，只有 0.8% 在 0 左边；中间 95% 落在 +1.8 ~ +17.5。如果只是运气，重抽结果会围着 0 左右摆；现在几乎全在右边，所以不像运气。

换题重算，几乎每次都是偶数位更好。

办法二：算「碰巧」的概率

1.6%

p = 0.016。假如两边其实一样准，做 100 次这样的实验，只有约 1.6 次会碰巧测出 +9.6 这么大的差距。习惯上低于 5% 就说「不太可能是碰巧」。

办法三：逐题看

把 64 道题分开算，看有几道是偶数位更好。

赢的题数是输的两倍多，不是靠一两道题。

具体怎么算的

同一道题会被考 16 次（8 个位置组 × 2 轮），这 16 个答案彼此相关，不能当成 16 个独立样本。所以抽签时整道题一起抽：抽中一道，就把它 16 个答案一起带进来。这叫 bootstrap（自助重采样）。

p 值 = 假如其实没差别，碰巧看到这么大差别的概率。95% 区间 = 把 10 万个差距从小到大排，去掉最小的 2.5% 和最大的 2.5%，剩下的范围。

五、第二个实验：续写代码，没复现

论文的第二个实验，我们没看到同样的规律。

前面是答题，这个是续写代码：给模型看半行代码，让它填下一个词。原文这里填 8，表示用 FP8（8 位浮点：用 8 个二进制位存一个数，省显存）；如果填 32，就变成 FP32（32 位浮点：更精确，但更占显存）——那就写错了。

T.Cast(compute_dtype, T.Cast(FP▮

▮ = 模型要填的下一个词：8 或 32。

做法：在代码前面垫一段填充文本，长度 L 从 23 个 token 加到 38 个。每换一个 L，重新问一次。论文附录 B.2 的对话实验说：L 是奇数答 8，偶数答 32；也就是每加一个 token，答案翻一次。

名词表
token（词元）
模型读写文本的最小单位。一个英文单词通常算 1 个。
ℓ（前垫长度）
目标记录前面垫了多少个普通 token，8–40。后面用 48−ℓ 个后垫补齐，总长不变。
位置
目标记录第一个 token 在提示里的序号，从 0 数。
位置组（论文叫残基，residue）
位置 ÷ 8 的余数，0 到 7，一直循环。例：位置 24 → 组 0，位置 29 → 组 5。
题
一对固定的「键:值」。全实验共 64 道，每道各考 16 次。
bootstrap（自助重采样）
整组抽签：把 64 道题有放回地随机抽 64 道，重算差距，重复很多次，看结果波动多大。
p 值
没差别时，碰巧看到这么大差别的概率。越小越可信。
95% 区间
重复抽样时，约 95% 的结果会落在这个范围。
百分点
两个百分比直接相减的单位。80% 减 70% = 10 个百分点（不是 10%）。
FP8
8 位浮点，比常用 16 位更省显存。
