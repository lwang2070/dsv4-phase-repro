二、原理：记忆每隔几步重来一次

这一节从注意力（attention）讲起：先看模型原本怎么记住前文，再看 V4 为了省显存改成了什么，最后说明为什么某些位置会被系统性漏掉。

1. 先说 attention：每个 token 回头看前文

attention（注意力）是模型读上下文的核心动作：模型处理一个 token 时，会让它回头看前面的 token，判断哪些和自己有关，再把有关的信息按相关程度混进来。只能看前面，是因为回答还没写出来：生成第 n 个 token 时，第 n+1 个及以后的 token 还不存在。这种「只看前文」的做法叫 causal attention（因果注意力）。

举个具体的例子。句子是「小明把钥匙放进抽屉，因为它不好找」。读到「它」时，模型要判断「它」指什么。它会把「它」和前面每个词逐个比对：和「钥匙」最对得上，和「抽屉」也有关系，和「小明」关系不大。于是「钥匙」拿到最大的权重，「它」这个位置就混进了大量「钥匙」的信息。

这是打比方，帮你看懂「按相关程度混进来」。真实的 attention 只算向量相似度，不真的做语法分析；「它指钥匙」是很多层、很多个头叠加之后的结果。

这个比对靠三样东西。每个 token 都会算出三组数字（向量，也就是一串数，表示这个 token 的特征）：

  • query（查询）：我现在想找什么。好比你要找「红烧肉怎么做」。
  • key（键）：我这里有什么。好比每本书书脊上的标签。
  • value（值）：我实际提供的内容。好比书里的正文。

拿 query 和前面每个 token 的 key 算相似度，得到一个分数，分数越高越相关；再把这一排分数换算成加起来等于 1 的权重；最后按权重把各家的 value 混起来，作为这一层的输出。

为什么要有 KV 缓存。生成回答时，模型一次只吐一个 token。每吐一个，都要拿它的 query 和前面所有 token 的 key 比一遍，再按权重取 value。前面的 token 没变，它们的 key 和 value 也不会变。所以模型算一次就把它们存下来，后面直接查表。这份存下来的键和值就是 KV 缓存（key-value cache）。

缓存的问题：越存越大。序列有多长，缓存里就存多少条键和值；模型有几十层，每层各存一份。上下文到十几万 token 时，这份缓存本身就非常占显存，而且每次生成还要把它读一遍。

DeepSeek-V4 的省法：把相邻的几个 token 先压成一条。与其每个 token 都留一份键和值，不如把连续的一小段 token 合起来，压成一条摘要（里面存的是这一段 token 的键和值）。远处的 token 查摘要，最近的一小段仍看原始 token，保证刚说过的话不被压糊。代价是细节变糊：原来能精确看到每个词，现在看到的是几个词混在一起的样子。

先认几个词：一次压缩覆盖的那段连续 token 叫窗口（也叫块）；每隔多少 token 压一条新摘要，叫步长 S；相位是 token 位置除以 S 的余数，只有 0 到 S−1 几种。

缓存条目因此变成每 S 个 token 一条：S=2 时只剩原来的一半，S 越大省得越多，丢的细节也越多。

一句话总结这条机制：模型不把每个 token 单独存起来，而是每隔 S 个 token 压成一个摘要。token 的相位不同，被记住的清楚程度就不同；相位每 S 个重来一次，所以强弱也每 S 个重来一次。

下面这几条式子，算的就是「怎么把一块 token 压成一条摘要」。

2. 公式：一条摘要怎么算出来

上一小节说到，V4 把相邻的几个 token 压成一条摘要。这一小节算的是键，值的算法一样。一块有 8 个 token（格子 0–7），每个 token 带一串数字。压缩就是按学到的偏好给这 8 个 token 分配权重：权重大的 token，在摘要里声音大。

先认符号：j 是第几块；i 是块里第几格（0–7）；W 是一块有几格，这里是 8；h 是 token 的向量（一串数字，表示这个 token 的特征）；Z、b、C 是训练学到的参数；s 是给每个 token 打的分数；α 是分数换算出的权重；K̂ 是压出来的键摘要。s、α、Z、b、C 右上角的 K 表示「算键时的量」，算值时换成 V。

记号上：Z 和 h 写在一起表示相乘（点积），对应位置的数相乘再相加；Z 有多行时，每行各算一次。Σ 是把各格的结果加起来，⊙ 是每个数分别相乘。

整套计算分三步：给块里每个 token 打分 → 把分数变成权重 → 按权重加起来。论文写成三条式子：

两个公式差在哪？公式 (1) 的打分参数 Zi 直接乘 token 向量；公式 (5) 把它换成一个固定的偏好向量 cr。论文用简化模型是为了能证明，不是为了更准。简化模型里窗口不重叠，一块正好 S 格，所以这里的 S 既是步长也是窗口大小；V4 实际是窗口 8、步长 4，V4.1-Flash 步长 2。

关键在 c 里有一份对所有 token 都一样的成分，相当于给每一格设了一个固定加分：不管来什么内容，第 r 格都自带一点优势。内容分加上固定分，位置偏好就出现了（第 9 页）。

举个 4 格的例子（格子编号 1–4）。四个分数是 0.2、0.6、1.9、0.5，softmax 后权重是 0.11、0.16、0.59、0.14，第 3 格拿走 59%。换一块内容，分数变成 1.0、0.3、1.8、0.2，权重变成 0.24、0.12、0.53、0.11，赢的还是第 3 格。

论文还加了一个假设：所有 token 的向量都含一个共同成分 κ（公式 4，第 9 页）。所以任意两个不同 token 的点积都接近 κ，而不是 0。c 里沿着这个共同方向的分量，对每个 token 都加同样的分——这就是上面说的固定加分。

论文证了两条定理（定理 = 用数学证明的结论，只在假设范围内成立；第 9 页）：

  • 定理 1（最优压缩是集中的）：不限定打分方式，只要求每块的权重可以自由选，而且这些权重在看不到问题时就要定好。这时最优的压缩会把键的权重全压在第 r 格，值的权重全压在第 r+1 格。每个头只「看」一格，键和值错开一格。
  • 定理 2（训练会走到固定偏好）：把打分限制成公式 (5) 的简化模型，从随机初始化开始训练。梯度流（gradient flow，学习率很小的梯度下降；学习率 = 每步调参数的幅度，可以理解为按让误差变小的方向，一点点调参数）会走到这个状态：每个头固定喜欢某一格，键固定在 r 格、值固定在 r+1 格，换内容也不变。

参考模型的头没有这么极端，但方向一致。回到相位：目标 key 落在第 r 格时，它在摘要里声音最大；位置挪一格，它就掉进权重小的格子。第 5 小节「相位为什么会影响记忆」会把这个过程画出来。

3. DeepSeek-V4 里有两类注意力层
4. 切块：每 S 个 token 开一个新摘要

举个具体例子。目标记录的键在位置 63,976 + ℓ（ℓ 读作 ell，是目标记录前面垫的普通文本长度，后面「三、方法」会细说）。ℓ 从 8 改成 9，键就从 63,984 挪到 63,985。内容没变，和问题的距离也没变；变的只是相位：63,984 除以 2 余 0，相位 0；63,985 除以 2 余 1，相位 1。

5. 相位为什么会影响记忆

回到任务本身。提示里塞了很多「键: 值」对，问题给出键，模型要把对应的值答出来。做法分两步：先用问题的 query 和缓存里的键比，让最像的键拿到最大权重；再从对应的记录里把值取回来。

压缩在这两步上各埋了一个坑。

坑一：键和值可能落进两条摘要。在这个任务里，每个键后面紧跟它的值。如果压缩窗口把这对拆开，装着键的那条摘要里就没有值；模型即使找到了键，也很难取到对应的值。论文的参考模型用不重叠窗口，只有最后一个相位的键值对会跨窗。跨窗确实更难，但只解释一小部分差距：同一个窗口内的其他相位，准确率照样能差 50 多个百分点（第 6 页）。所以还有第二个坑。

坑二：同一个窗口里，每一格的分量不一样。第 2 小节说过，摘要不是平均，而是按权重加权。论文的解释是：目标 token 落在权重高的格，它在摘要里声音大；落在权重低的格，就被同窗口里别的 token 稀释。目标信号变弱，query 和摘要的匹配分数下降，模型可能找不到它。不同的头峰值格不同：目标落在某格时，有的头还能把它捞起来，有的头帮不上。哪些头帮得上，取决于相位。在论文的参考模型里窗口不重叠，格子的编号就等于相位；V4 的窗口有重叠，一个 token 会进多条摘要，但它在每条摘要里落在哪几格，仍然由相位决定。所以相位一变，准确率就跟着变。这是论文的机制解释，不是已经证明的定论。

6. 所以周期等于步长

步长 S 是几，相位就有几种：V4 是 4 种，V4.1-Flash 是 2 种。每 S 个 token，分组从头再来一次，强弱也就跟着重复。论文用两组对照支持这个解释：换成不压缩的完整注意力，周期消失（第 5 页图 3）；把第 3 到 23 层（层号从 0 数）每个头对各格的偏好整体平移一格，准确率的低谷也跟着平移（附录 H 图 19）。

我们的结果正好对上：偶数位置 80.0%、奇数位置 70.4%，就是 S=2 的两个相位。第二个实验里，填充每多 1 个 token，完成点的相位就翻一次，所以答案在 8 和 32 之间交替。

完整架构（MoE，混合专家：每层只激活一部分小网络）论文没有展开，这里也不画；上面只画和相位有关的注意力部分。

五、这个差距是真的吗

是真的，不是运气，也不是靠一两道题。
但具体多大不确定：重做一次，可能落在 +1.8 到 +17.5 之间。

好比两个班考试：甲班平均 80 分，乙班 70 分。你会追问两件事：这 10 分会不会是抽到的学生碰巧强？会不会是一两个学霸拉高的？下面三个办法，就是查这两件事。

办法一：换一批题，重算

64 道题（每道是一对固定的「键:值」）就是我们的「学生名单」。把 64 道题有放回地随机重抓 64 道（同一道可能被抓到多次），重算一次「偶数位减奇数位」。重复 10 万次，得到 10 万个差距。

横轴 = 一次重算得到的差距（百分点）。竖轴 = 有多少次重算落到这个差距，柱子越高越常见。0 = 两边一样准。10 万个差距里，99.2% 在 0 右边，只有 0.8% 在 0 左边；中间 95% 落在 +1.8 ~ +17.5。如果只是运气，重抽结果会围着 0 左右摆；现在几乎全在右边，所以不像运气。

换题重算，几乎每次都是偶数位更好。

具体怎么算的

同一道题会被考 16 次（8 个位置组 × 2 轮），这 16 个答案彼此相关，不能当成 16 个独立样本。所以抽签时整道题一起抽：抽中一道，就把它 16 个答案一起带进来。这叫 bootstrap（自助重采样）。

p 值 = 假如其实没差别，碰巧看到这么大差别的概率。95% 区间 = 把 10 万个差距从小到大排，去掉最小的 2.5% 和最大的 2.5%，剩下的范围。

做法：在代码前面垫一段填充文本，长度 L 从 23 加到 38 个 token。L 每加 1，完成点（模型要接下去写的那个位置）往后挪 1 个 token。论文附录 B.2 的 V4.1-Flash 对话实验里，A 组（也就是我们用的这种填充）是：L 奇数答 8，偶数答 32；D 组在 L=23–29 全答 8，之后也按奇偶交替（16 个里对 11 个）。

第一次为什么看反了

填充文本本身以换行结尾。我们又在它和代码之间加了两个换行，等于多空一行；完成点整体后移 1 个 token，和我们按 L 分的奇偶正好错开。旧数据看起来像周期 4，不稳定，所以当时判成了没复现。

改成 1 个换行后，完成点位置正好等于论文写的 1004 + L。脚本现在每次都会断言这个等式：scripts/prob_sweep.py。

顺便试了 FIM

FIM（fill-in-the-middle，补中间）：给模型前文和后文，让它填中间。我们在代码后面加一句和答案无关的后缀 # end of file，长度 24–39，16 个长度全部答 8，概率差最低 +0.99。

加上后缀之后，隔位交替消失了。但后缀不是唯一变的东西：在我们的 V4.1-Flash-1017 上，原始格式（不套聊天模板、没有指令、走另一个端点）也全答 8。所以能说的只是「离开『对话格式 + 只给前文』，这个弱点就没出现」，不能把原因单独归给后缀。论文里另两种设置是 4 个位置的周期，不是隔位交替：原始模型 + 原始前缀（附录 B.1），以及聊天版的 V4-Flash-0731（附录 B.2）。我们测的是 V4.1-Flash-1017，模型和格式都不同，不能直接对照。

补充：原始格式跑 2 遍，长度 24–39，16 个长度也全部答 8。以上 9 遍共 144 次。

名词表
token（词元）
模型读写文本的最小单位。一个英文单词通常算 1 个。
ℓ（前垫长度）
目标记录前面垫了多少个普通 token，8–40。后面用 48−ℓ 个后垫补齐，总长不变。
位置
目标记录第一个 token 在提示里的序号，从 0 数。
位置组（论文叫残基，residue）
位置 ÷ 8 的余数，0 到 7，一直循环。例：位置 24 → 组 0，位置 29 → 组 5。
题
一对固定的「键:值」。全实验共 64 道，每道各考 16 次。
bootstrap（自助重采样）
整组抽签：把 64 道题有放回地随机抽 64 道，重算差距，重复很多次，看结果波动多大。
p 值
没差别时，碰巧看到这么大差别的概率。越小越可信。
95% 区间
重复抽样时，约 95% 的结果会落在这个范围。
百分点
两个百分比直接相减的单位。80% 减 70% = 10 个百分点（不是 10%）。
FP8
8 位浮点，比常用 16 位更省显存。
KV 缓存
模型读完前文后存下的「键」（key）和「值」（value）。后面提问时直接查，不用重读前文。
窗口 / 步长 S
窗口 = 一次压缩覆盖的一段连续 token；步长 = 每隔多少 token 开一个新窗口。
相位
token 位置 ÷ 步长 S 的余数。S=2 时，位置 0、2、4… 相位 0，位置 1、3、5… 相位 1。
摘要
一个窗口压成的一条 KV，后面检索时查它。
向量
一串数字，表示一个 token 的特征。例：[0.2, −0.5, 1.1]。
点积
两个向量对应位置的数相乘，再加起来。结果越大，两个向量越「合拍」。
softmax
把一排分数变成一排权重：每个分数取 e 的幂次，再除以总和。结果都为正，加起来等于 1。
熵 H / 有效格数
熵衡量权重有多分散，有效格数 = exp(熵)，意思是「实际上用到了几格」。全压一格 = 1，均分 4 格 = 4。
定理
从假设出发、用数学证明的结论。定理成立的范围就是它的假设；换掉假设不一定成立。
CSA / HCA
CSA = 压缩稀疏注意力，窗口小、看得细；HCA = 重度压缩注意力，128 个 token 压成 1 条。
注意力头
注意力里并行的小通道，每个头自己学一套权重。
MoE（mixture of experts，混合专家）
模型每层有一堆小网络，每次只激活其中一部分，省算力。
温度（temperature）
控制随机性的旋钮。温度 0 = 永远取概率最高的词；温度 1 = 按模型本来的概率来。
FIM（fill-in-the-middle，补中间）
给模型前文和后文，让它填中间。DeepSeek 的 /beta/completions 接口带 suffix 参数时就是这种用法。
